# Eventless Payload-Adaptive MHE-NMPC 实验计划

> 版本：v1.2
> 日期：2026-09-15
> 修订：v1.1 按现有数据/代码现状重写 E0（§5），并同步 §9.1、§13、§14；v1.2 新增 §4.1 baseline 实现现状、§4.2 C 臂拆分、§9.5 故障注入器现状，并把"补齐实现"写进 §14 第 1 步
> 目标：用控制变量清晰的 baseline、消融实验和实机验证，分别证明 evidence-gating、eventless detection 与 first-moment parameterization 的贡献。

## 1. 实验目标与范围

本实验计划回答三个相互独立的问题：

1. 释放命令不能代表物块已经脱离时，等待物理证据是否能避免提前清除载荷模型？
2. 没有收到 release command 时，始终运行的检测器是否能识别真实载荷脱落？
3. 使用一阶质量矩 `s = m_P r_xy`，是否比只使用质量或直接估计 CoM 偏移更稳定、更安全？

实验分为四层：

1. 离线日志回放：比较参数化和检测器，不引入闭环轨迹差异；
2. PX4 SITL：完成大样本统计、危险故障和鲁棒性扫描；
3. HIL/系留：验证真实计算时序、遥测和故障逻辑；
4. 自由飞行：只验证最关键、风险可控的系统结论。

不要求把所有 SITL 条件搬到实机。实机用于验证关键机制，统计规模和危险 baseline 主要由 SITL/HIL 支撑。

## 2. 核心假设

| 假设               | 核心问题                                          | 核心比较                             | 主要终点                             |
| ------------------ | ------------------------------------------------- | ------------------------------------ | ------------------------------------ |
| H1 Evidence-gating | 物理证据能否避免 release command 导致的提前清模？ | CMD-Immediate vs CMD-Evidence        | 真实脱离前接受空载模型的比例         |
| H2 Eventless       | 没有 release command 时能否检测载荷脱落？         | CMD-Evidence vs Eventless-Full       | 时限内检出率，同时满足误报率约束     |
| H3 First moment    | `s = m_P r_xy` 是否优于质量证据或 CoM 参数化？  | P-noMoment/CoM-MHE vs Eventless-Full | 错误 EMPTY、漏检、检测时间和估计失败 |

### 2.1 H1：Evidence-gating

定义：

- `t_cmd`：release command 发出时刻；
- `t_sep`：物块真实脱离时刻；
- `t_accept`：控制器接受“载荷已脱离”并切换空载目标的时刻；
- `t_empty`：经过滤波与速率限制后，控制器实际使用的参数进入空载容差带的时刻。

若：

```math
t_{accept} < t_{sep},
```

则记为一次 premature clear。`t_accept` 用于判断语义错误，`t_empty` 用于计算错误模型实际持续时间。

永久卡死时 `t_sep = +∞`，任何 EMPTY 接受都属于 premature clear。正确行为是保留 loaded model，并在证据不足时进入 `UNRESOLVED`。

### 2.2 H2：Eventless

无命令脱落的一次及时检出定义为：

```math
t_{sep} < t_{accept} \le t_{sep} + \tau,
```

并且在 `t_sep` 之前没有错误 EMPTY。

H2 必须同时验证：

1. 无命令脱落的检出率；
2. 持续带载、无真实脱落时的误报率。

不能通过单纯降低阈值换取高检出率。CUSUM/GLR 与 proposed detector 应在独立 calibration set 上调到相同 false-alarm 水平，再进入冻结测试集。

### 2.3 H3：First moment

H3 分为两个子问题：

- H3a 参数化：载荷趋近于零时，`m + s` 是否比 `m + r_xy` 更稳定；
- H3b 检测证据：加入 moment vote 是否降低错误 EMPTY 和总体安全失败，同时不引入不可接受的检测延迟。

释放时 `m_P -> 0`，载荷 CoM 偏移 `r_xy` 失去物理定义，而：

```math
s = m_P r_{xy} \rightarrow 0
```

仍具有明确含义。实验需要直接验证这一数值与闭环优势，不能只进行概念论证。

## 3. 成功、失败与时间限制

### 3.1 两个截止时间

建议区分：

- `tau_mission`：在不触发 brake-to-hover 的情况下完成确认的最大时间；
- `tau_safe`：允许进入 `UNRESOLVED` 和刹停，但必须保持安全的最大时间。

当前系统可以暂定：

- `tau_mission = 12 s`，对应进入 `UNRESOLVED` 前的时限；
- `tau_safe = 17–20 s`，覆盖刹停及悬停确认过程。

最终数值应依据允许位置误差、飞行区域、障碍物距离、制动时间和执行器裕量确定，并在最终测试前冻结。当前 `12 s` 本质上是工程超时，不能未经论证直接称为物理安全时限。

### 3.2 结果分类

- 任务成功：在 `tau_mission` 内确认，不中断参考轨迹；
- 安全成功：可能进入 `UNRESOLVED` 并刹停，但无提前清模、越界或坠机；
- 安全失败：提前清模、超过 `tau_safe` 未安全处理、越界、坠机或严重约束违反。

建议定义端到端失败复合终点：

```math
Y_{fail} =
\text{premature clear}
\lor \text{超过 }\tau_{safe}\text{ 未解决}
\lor \text{坠机/越界}
\lor \text{估计器或求解器导致安全终止}.
```

## 4. 公平 baseline

除被研究因素外，所有方法必须统一使用：

- 最终版 NMPC；
- 最终版 MHE 和相同状态/测量输入；
- rotor-speed reconstructed `T_phys`；
- 相同滤波器、slew-rate limit 和时间戳检查；
- 相同 inner-loop body-rate scheduling；
- 相同 health gate、stale-frame 和 `UNRESOLVED` 逻辑。

| 组别              | 模型清除逻辑                                  | 用途                       |
| ----------------- | --------------------------------------------- | -------------------------- |
| O：Oracle         | 真实`t_sep` 时触发空载目标                  | 性能上界，不属于可部署方法 |
| A：CMD-Immediate  | 收到命令立即触发空载目标                      | 验证 evidence-gating       |
| C：CMD-Evidence   | 收到命令后才启动与 P 相同的检测器             | 隔离 eventless 贡献        |
| P：Eventless-Full | 检测器在 loaded flight 中始终激活             | 完整方法                   |
| P-noMoment        | 与 P 相同，但 detector 不使用 moment evidence | 隔离 moment vote           |
| CUSUM/GLR         | 相同传感信号上的标准变化检测                  | 标准检测 baseline          |

原论文 legacy Arm A 同时改变 MHE、geometry update 和内环调度，只保留为附录中的历史端到端参考，不再承担主要因果结论。

关键比较：

- A vs C：持续物理证据是否避免提前清模；
- C vs P：eventless 是否在无命令脱落中提供额外能力；
- P-noMoment vs P：first-moment evidence 是否必要；
- CUSUM/GLR vs P：复杂检测逻辑是否优于标准方法；
- O vs P：估计和确认延迟造成的性能损失。

### 4.2 C 臂拆分

§4 表中 C 的定义是"收到命令后才启动与 P 相同的检测器"，而已跑批次的 C 实际使用另一种确认判据，因此 C vs P 同时改变了"是否依赖指令"与"检测器类型"两个因素（夜间批次 C 确认延迟 4.3 s、P 11.5 s，差异可能部分来自检测器）。拆为：

- **C-same**：只隔离 eventless，承担 C vs P 的因果比较；
- **C-thrust**：更快的"带确认指令触发"对手，保留作为强 baseline。

H2 的无指令脱落场景中 C 两臂按构造都检出 0，该比较只说明"指令触发做不到"；eventless 检测器本身的价值必须对 Watchdog 与 CUSUM/GLR 在相同误报率下比较。

> v1.1 修订（2026-09-15）：按现有数据与代码现状重写。原 5.2 的 360 格全因子网格在现有设施下不可执行（SITL 中 `r_z` 固定、偏心不可精确设定、partial release 没有原始流），改为“已有日志回放 → 保真度门 → 新采集冻结集 → 合成扫参补盲区”四段。

### 5.1 三个估计器的定义（只差参数化，其余逐字相同）

| 估计器      | 被估参数        | 代码现状                    | 配置                                                                            |

公平性约束（实现 `MHE-CoM` 时必须满足，写进代码注释并在结果表中列出）：

- 相同 `N=20, dt=0.1`、R/Q、质量到达代价、`m_min/m_max`、`A=μ r_z²` 的 frozen 处理、`r_z` 弱先验；

- 外层节点逻辑（质量种子、窗口力平衡重锚、health gate）三臂共用同一实现。

- W-c 是 H3a 的对照：`r_xy = 0` 时三种参数化理论上等价，若 `MHE-CoM` 在这里也出问题，说明问题来自实现而非参数化。
- partial release 必须重新采集：09-15 四箱批次没有原始流。

**E0-c 合成扫参（补 SITL 盲区，只作机制说明）**

SITL 中 `r_z ≈ 0.48 m` 固定、偏心只能落在 0.10–0.15 m，原计划的竖直距离 0.08/0.12/0.16 m 与偏心 0/±0.05 m 无法在 SITL 覆盖。沿用 `test_mhe_geom_coupled_standalone.py` 的全 3×3 惯量真值 plant，生成一次冻结数据再喂三种估计器：

- `m_P ∈ {0.15, 0.30}`，`r_xy ∈ {0, 0.05, 0.10}`（+x、−y 两方向），`r_z ∈ {0.10, 0.12, 0.48}`；
- 事件 attach → carry → full release，悬停与正弦机动两种激励；
- 每格 5 个噪声种子。

合成结果不与 SITL 数字合并，只用于说明趋势是否与 SITL 一致；实机 `r_z = 0.10–0.12 m`（§10.3）的结论须等 H1 真实日志回放。

### 5.3 推力映射失配（并入 E0，离线零成本）

09-15 夜间批次已证实 ±5% 估计器推力增益会在两个方向都让接口失效（0.95：载荷不可见；1.05：幽灵 +0.09 kg、放不下来）。离线回放可以只缩放喂给估计器的 `T_phys/tau_phys`，因此在 E0-a/E0-b 数据上直接扫：

```math
k_E/k_P \in \{0.95,0.97,0.98,0.99,1,1.01,1.02,1.03,1.05\},
```

回答“三种参数化中哪一种的可用标定误差带最宽”。这只覆盖 estimator-only 失配；`k_E = k_C ≠ k_P` 的闭环部分仍在 E4。

### 5.4 指标

估计精度（按段报告：空机、attach 后 0–5 s、carry 稳态、release 后 0–5 s、release 后稳态）：

- `m, s, c_xy` 的 bias、RMSE；`MHE-CoM` 的 `s` 由 `m_P⁺ · r_xy` 换算后同口径比较；
- 以物理 attach/detach 为零点的入带时间（`m` ±2%、`|s|` ≤ 0.003 kg·m），未入带按右删失处理，不丢弃；
- release 后残余 `|s|` 与残余 `|c_xy|`，以及 `m` 被推离空机值的幅度（检验“m 被拿去当几何旋钮”）；
- 机动中 `|s|` 被撑高到带载参考值的比例（09-15 已见 4 m/s 下 60%–100%）。

数值健康：

- `m` 触碰 `m_min/m_max`、`s`/`r_xy` 触碰箱约束的帧比例；
- solver status≠0 比例、重锚次数、最长连续重锚串、unhealthy 持续时间；
- Gauss–Newton Hessian 条件数：release 前 2 s 与后 2 s 分开报告（H3a 的直接证据）；
- 单次求解 P50/P95/P99/max 与 100 ms deadline miss（离线计时须在同一台机器、单进程串行测）。

下游证据（只作次要终点，主结论留给 E2）：

- 把三种估计输出分别喂给同一个冻结的 release detector，报告 premature clear、漏检和检测延迟；
- 注意 `MHE-m` 没有 moment 证据，只能喂质量域判据，这一臂的检测结果即 E2 中 P-noMoment 的离线近似。

### 5.5 判定规则（E0-b 开跑前冻结）

- H3a 成立：release 后 2 s 内 `MHE-s` 相比 `MHE-CoM` 的 solver 失败/触界复合终点更少（配对 exact McNemar），且 W-c 居中工况两者无差异；
- `MHE-s` 相对 `MHE-m` 的收益须在 carry 稳态 `m` bias 上体现，且方向与 08-31 coupled vs legacy 批次一致；
- 若 E0-b 中 `MHE-CoM` 与 `MHE-s` 无可检测差异，论文措辞为“一阶质量矩在本数据上未表现出可测优势，其价值在于 `m_P→0` 时参数仍有定义”，不得写成“优于”；
- 4 m/s 与 0.30 kg/4 m/s 结果分开报告。

### 5.6 闭环验证

离线结论冻结后，只选 `MHE-CoM` 与 `MHE-s` 在 W5 上各跑 8 个配对区组闭环，终点为 release 后 5 s 内的 position-error AUC、饱和持续时间和坠机。`MHE-m` 不做闭环（历史批次已知其 drop 后会把 `m` 压向下界）。

### 5.7 实施清单

1. `scripts/gripper/e0_replay.py`：读原始四流 + proximity 真值，复刻 `timer_cb` 取样，三档估计器串行回放，输出逐帧 CSV 与每轮汇总；

3. 保真度门脚本与报告；
4. E0-a 开发集结果 → 冻结代码、阈值与评分脚本（记录 commit）；
5. 预注册文件 `E0_参数化_预注册_<日期>.md`，再采集 E0-b；

## 8. E3：控制性能实验

## 9. E4：鲁棒性与 Sim-to-Real

### 9.1 推力模型失配

区分 plant、command inversion 和 estimator 使用的推力系数：`k_P, k_C, k_E`。

Estimator-only 扫描：

```math
k_E/k_P \in \{0.95,0.97,0.98,0.99,1,1.01,1.02,1.03,1.05\}.
```

另外测试：

- `k_E = k_C != k_P` 的共同映射误差；
- 随速度变化的有效推力下降；
- 随电池电压变化的慢漂移；
- 单个电机推力系数偏差。

输出 operating-envelope 曲线：标定误差—载荷识别率—释放确认率—误报率。

Estimator-only 这一项在 E0 离线回放中完成（§5.3），这里只做闭环部分：`k_E = k_C != k_P`、速度相关推力下降、电压漂移和单电机偏差。

### 9.2 RPM 与时间同步

- 相对 RPM 噪声：0、0.5%、1%、2%、5%；
- 共模 bias：±1%、±2%、±5%；
- 延迟：0、10、25、50、100 ms；
- timestamp jitter：0、10、25 ms；
- 丢包：0、5%、10%、20%，zero-order hold；
- 量化：10、50、100 RPM。

同时报告 RPM 误差、重构 `T_phys` 误差以及最终 `m,s` 偏差。由于算法使用 `omega^2`，还应检查平方项带来的噪声正偏置。

### 9.3 风扰动与不可辨识边界

分别测试：

- 横风；
- 0.5 s、2 s 的短时垂直阵风；
- 10 s 持续垂直气流；
- 风发生在释放前、跨越释放时刻和释放后。

持续垂直力可能与载荷变化结构性混淆。合理目标是：短阵风不导致 premature clear，证据冲突时进入 `UNRESOLVED`；对于不可辨识的持续垂直气流，报告允许扰动力边界，不宣称任意条件下都能正确辨识。

### 9.4 组合最坏条件

完成单因素筛选后，运行一个实测范围内的组合条件，例如：

- 2% thrust-map error；
- 1% RPM noise；
- 40 ms delay；
- 5% packet loss；
- 短时阵风。

组合条件建议至少运行 30 次确认性试验。

## 10. 实机偏心载荷装置

### 10.1 推荐结构

采用“中心永久释放机构 + 整体可脱离刚性标定模块”：

```text
               飞行器本体
            Body-frame origin O
                    |
          中心永久释放机构
          定位销 + 防转机械锁
                    |
          可脱离轻质刚性框架
                    +----------● 紧凑配重
                    |          <--- r_xy
                    |
                    v r_z
```

永久释放机构计入 bare-airframe 参数。水平导轨、竖直导轨、配重和可脱离连接件整体释放，从而保证改变配置时空载飞行器保持不变。

连接必须限制六自由度运动，使用至少两个防转定位销和一个承重锁。不要使用绳索或可转动的单点磁吸，否则会引入 slung-load 或柔性模态。

### 10.2 质量与质心真值

整个 detachable module 的质心为：

```math
r_P = \frac{m_w r_w + \sum_i m_i r_i}{m_P},
\qquad
m_P = m_w + \sum_i m_i.
```

真实一阶质量矩：

```math
s_x = m_P r_x,\qquad s_y = m_P r_y.
```

`r_z` 是 bare-airframe 参考原点到整个 detachable module 质心的距离，不是竖直杆的长度：

```math
r_z = z_{interface} + z_{module,CoM}.
```

每种机械配置均须：

1. 称量整个可脱离模块；
2. 用刀口平衡法测量 x/y 质心；
3. 用两个悬挂方向及铅垂线测量三维质心；
4. 用固定治具将质心位置转换至飞行器 body frame；
5. 保存配置编号、质量、质心、安装方向和照片。

### 10.3 首轮实机配置

- `m_P = 0.15 kg`；
- `r_xy = 0.05, 0.10 m`；
- `|r_z| = 0.10–0.12 m`；
- 偏心方向：`+x, -x, +y, -y`；
- 速度：hover，随后增加至 1–2 m/s。

偏心静态配平力矩近似为：

```math
\tau_{trim} \approx m_P g r_{xy}.
```

0.15 kg、0.10 m 时约为 0.147 Nm；0.30 kg、0.10 m 时约为 0.294 Nm。后者会消耗较大的滚俯力矩裕量，不用于首轮自由飞行。

## 12. 统计设计

### 12.1 实验单位与配对

统计单位是一次完整独立航次，不能把 10 Hz/100 Hz 控制样本当成独立样本。

每个 `scenario-seed` 构成一个随机区组，固定：

- 质量、偏心距离和方向；
- 飞行速度和轨迹；
- release command 与真实脱离时刻；
- 风扰、噪声和推力系数误差；
- 初始状态和随机种子。

所有待比较方法在同一区组运行，形成配对数据。运行顺序预先随机化。硬件实验进一步按日期、载荷装配、电池批次和飞行 session 分区组。

### 12.2 数据隔离与样本量

- 开发/先导集：12–15 个配对区组，用于调阈值和估计方差，不进入最终检验；
- H1/H2 二元主要终点：理想情况下每个假设族 60 个确认性配对区组；
- 连续误差和检测时间：至少 48 个配对区组；
- 硬件资源有限时，每场景 8–10 次只能称 feasibility validation；
- 若要支持误报率低于 0.1 次/小时，每种 detector 需要约 30 小时零误报 loaded exposure。

最终测试开始后冻结：代码版本、参数、阈值、随机种子清单、排除规则和分析脚本。

**配置断代与批次混用禁令（2026-09-15）**：

- 窗口力平衡种子自 commit `9ce9406`（2026-09-15 11:20）起默认开。开发集与确认性批次**都必须**在该 commit 之后、以相同种子配置新采集；09-15 之前的任何批次既不能作开发集调阈值，也不能并入确认性检验，只能作为探索性/历史对照单独报告；
- 反向同理：若确认性批次需要 seed-off 对照臂，必须在冻结代码上显式 `MHE_SEED_FROM_THRUST=0 MHE_SEED_WINDOW_BALANCE=0` 重新采集，不得借用旧批次；
- 溯源：`experiment.env` 只记录**显式设置**的环境变量，默认值不进入，新旧批次在其中外观相同。已补两层生效值凭据（2026-09-15）：① provenance 目录新增 `experiment.effective_env.tsv`（`scripts/dump_effective_env.py` 静态扫描运行时包内全部 `os.environ.get`，逐变量给出生效值与 `explicit/default` 来源）；② MHE 节点启动日志 `[effective-env] seed_from_thrust= seed_window_balance= geom_coupled= N=`，以节点实际环境为准。批次归属判定优先看 ②，其次 ①；两者都缺的旧批次只能按 `workspace.git.txt` 的 commit 是否包含 `9ce9406` 判定。dirty 工作树批次一律不得进入开发集或确认集；
- 此后任何改默认值的提交都视为新的断代点，已采集的开发集随之作废，需按 §14 第 4–5 步重走。

### 12.3 失败与排除

采用 intention-to-test：通过起飞前检查并开始测试的所有航次进入主分析。

以下均属于方法结果，不能排除：

- 未形成 loaded reference；
- estimator unhealthy；
- `UNRESOLVED`；
- solver timeout/deadline miss；
- brake-to-hover；
- 释放后未确认；
- 越界、坠机或持续执行器饱和；
- 方法失败导致日志提前终止。

只有预先定义且明确与算法无关的基础设施故障可以排除，例如事件发生前日志进程崩溃或脱离执行机构没有按测试脚本动作。必须同时报告总尝试数、有效航次、每类失败和基础设施排除原因。

### 12.4 统计分析

- 配对二元终点：exact McNemar，并报告配对成功率差和 95% CI；
- 检测时间：漏检作为右删失，报告检测概率曲线与截至 `tau` 的 RMST；
- 跟踪误差：paired block bootstrap；
- false alarm：events/loaded flight-hour 和 Poisson exact CI；
- 综合条件效应：logistic/linear mixed-effects model；
- H1–H3 使用 Holm 校正控制 family-wise error rate 为 0.05。

所有结果报告原始计数、效应量和置信区间，不只报告 p 值，也不能只对成功航次计算检测延迟。

评分脚本 `scripts/gripper/score_lifecycle.py`：

- 输入 manifest 或 stamp，每个 stamp 输出一行（intention-to-test，不排除任何航次，只给 `infra_flag`）；
